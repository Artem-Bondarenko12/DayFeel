# MoodTracker — контекст проекта для нового чата

## 1. Что я хочу сделать

Я самостоятельно разрабатываю простое Android-приложение **MoodTracker** для ежедневного отслеживания настроения. Я начинающий в Android/Kotlin, поэтому мне важны понятные объяснения и обучение на практике, а не генерация всего проекта целиком.

**Основные требования:**
- Каждый день в **23:30** приложение присылает напоминание оценить день.
- Пользователь выбирает целочисленную оценку настроения в диапазоне **от −10 до +10**.
- По желанию добавляет текстовый комментарий о прошедшем дне.
- Данные сохраняются **локально** на устройстве и не исчезают при закрытии приложения.
- В приложении есть собственный календарь (не системный календарь телефона), где дни раскрашены от **красного (−10)** через **жёлтый (0)** к **зелёному (+10)**.
- По нажатию на день можно увидеть числовую оценку и комментарий.
- Интерфейс минималистичный, без регистрации, сервера или синхронизации.

## 3. Выбранный технологический подход

- **Язык:** Kotlin.
- **UI:** XML Layouts, визуальный редактор Android Studio, ViewBinding (НЕ Jetpack Compose).
- **Главный подход к навигации:** одна `MainActivity` и несколько `Fragment`, переходы через Android Navigation Component.
- **Локальная БД:** Room (поверх SQLite).
- **Состояние UI:** ViewModel, в первую очередь для календаря и экрана оценки.
- **Доступ к данным:** Repository → DAO → Room.
- **Календарь:** первоначально RecyclerView с GridLayoutManager(7) для месяца; недельный вид добавить позже.
- **Оценка:** SeekBar либо Material Slider.
- **Уведомления:** напоминание на 23:30; реализацию планировщика выбрать с учётом ограничений Android, разрешения POST_NOTIFICATIONS (Android 13+), точных будильников и восстановления после перезагрузки. В первой версии можно сделать без уведомлений.
- **Никакой чрезмерной архитектуры:** без обязательного Hilt, Clean Architecture, UseCases, сетевых API и микросервисов.

## 5. Модель данных

Одна запись на один календарный день.

```kotlin
@Entity(tableName = "mood_entries")
data class MoodEntity(
    @PrimaryKey val date: String,  // ISO yyyy-MM-dd, например 2026-11-02
    val score: Int,                 // целое число от -10 до +10
    val note: String?               // необязательный комментарий
)
```

При повторном сохранении оценки за тот же день запись **обновляется**, а не дублируется (например, Room `@Upsert`). Проверять диапазон −10…+10 при вводе и сохранении. Дату брать из локального времени устройства. Позже можно добавить timestamp редактирования, но сейчас он не обязателен.

Пример данных:

| date | score | note |
|---|---:|---|
| 2026-11-01 | 7 | Отличный день |
| 2026-11-02 | -3 | Устал |
| 2026-11-03 | 0 | Обычный день |

## 6. Архитектура и ответственность

```text
XML layout ↔ Fragment → ViewModel → MoodRepository → MoodDao → Room Database
             │
             └── Navigation Component → другие Fragment
```

- **XML:** положение, размер и оформление визуальных элементов.
- **Fragment:** привязка ViewBinding, обработка нажатий, показ UI, навигация.
- **ViewModel:** состояние и логика экранов, операции сохранения/чтения через Repository.
- **Repository:** точка доступа к сохранённым оценкам.
- **DAO + Room:** хранение и SQL-запросы.
- **MoodColorUtils:** перевод оценки −10…+10 в цвет шкалы и ячеек календаря.
- **Notification classes:** напоминания, отдельно от экранов.

## 7. Порядок реализации

1. **Старт проекта и UI:** убедиться, что проект использует Views/XML, создать `HomeFragment` и нарисовать стартовый экран (начать именно с него).
2. **Экраны:** сделать экран Mood с ползунком и полем комментария; экран Success; каркас Calendar.
3. **Навигация:** настроить переходы Home → Mood → Success, Home/Success → Calendar и возврат.
4. **Данные:** подключить Room, DAO, Repository, ViewModel; сохранять и читать настроение.
5. **Календарь:** месячная сетка, цветные даты, диалог деталей; затем недельный режим и третий режим после уточнения смысла.
6. **Уведомления:** ежедневное напоминание в 23:30, разрешения, проверка поведения на устройстве.
7. **Обработка ошибок, полировка интерфейса, тестирование на эмуляторе и телефоне.**

## 8. Контекст по Android Studio

- Я уже работал с Android Studio, Gradle Kotlin DSL (`build.gradle.kts`) и эмулятором.
- Ранее возникали проблемы с эмулятором Samsung и синхронизацией Gradle; не нужно возвращаться к эмулятору Samsung, если это не требуется.
- Я интересовался `ConstraintLayout` и визуальным режимом редактора; иногда кнопки «подтягивались» вверх из-за constraints. Поэтому объясняй разницу `LinearLayout` и `ConstraintLayout` и не предполагай, что я уже умею всё настраивать.
- При создании нового проекта нужен шаблон **Empty Views Activity** (или эквивалентный XML Views), а не шаблон с Compose.
- XML можно открывать в **Code / Split / Design**. Для простого центрированного Home подойдёт `LinearLayout`; для сложной компоновки — `ConstraintLayout`.
- Реальное имя пакета и текущее состояние файлов должны быть уточнены по проекту/скриншоту, если они не показаны в новом чате.
